# SUPABASE SCHEMA PLAN

Date : 2026-09-06
Mission : MISSION-02 - Conception cible PostgreSQL/Supabase

Ce document est uniquement une conception. Il ne doit pas etre execute sans validation explicite.

## 1. Principes cible

- Utiliser `auth.users` pour l'identite, les mots de passe, les sessions et les resets.
- Utiliser `public.profiles` pour les donnees applicatives admin/editor.
- Garder les IDs legacy MySQL quand cela simplifie la migration du contenu.
- Utiliser UUID seulement pour les utilisateurs Supabase.
- Activer RLS sur toutes les tables applicatives.
- Lire publiquement uniquement le contenu publie ou actif.
- Ecrire les donnees sensibles via Server Actions/API Next.js.
- Stocker les fichiers dans Supabase Storage, bucket `media`.
- Conserver MySQL intact jusqu'a validation finale.

## 3. Types recommandes

```sql
-- A valider avant execution
create type public.app_role as enum ('admin', 'editor');
create type public.appointment_status as enum ('new', 'reviewed', 'confirmed', 'cancelled', 'archived');
```

Alternative plus souple : remplacer les enums par `text` + `CHECK`. Pour ce projet, `text` + `CHECK` est recommande au debut afin de ne pas bloquer l'import si des valeurs historiques inattendues existent.

## 4. Tables principales proposees

### profiles

Objectif : remplacer `users` applicatif tout en utilisant Supabase Auth.

Colonnes proposees :

- `id uuid primary key references auth.users(id) on delete cascade`
- `legacy_user_id integer unique null`
- `name varchar(120) not null`
- `email citext unique not null`
- `role text not null check (role in ('admin','editor'))`
- `status text not null default 'active' check (status in ('active','disabled'))`
- `created_at timestamptz not null default now()`
- `updated_at timestamptz not null default now()`

Migration utilisateurs :

- Ne pas copier les mots de passe en clair.
- Ne pas publier les hashes dans les rapports.
- Creer les comptes Supabase Auth par invitation ou reset password.
- Stocker l'ancien `users.id` dans `legacy_user_id`.

## 7. Timestamps

Strategie :

- Utiliser `timestamptz` partout.
- Default `now()` pour `created_at`.
- Trigger `set_updated_at()` pour `updated_at`.
- Timezone applicative : `Africa/Johannesburg`, deja configuree en PHP.
- Stocker en UTC dans PostgreSQL/Supabase, afficher selon timezone applicative.

Trigger propose :

```sql
-- A valider avant execution
create or replace function public.set_updated_at()
returns trigger
language plpgsql
as $$
begin
  new.updated_at = now();
  return new;
end;
$$;
```

## 8. RLS cible

Fonctions de role :

```sql
-- A valider avant execution
create or replace function public.current_user_role()
returns text
language sql
security definer
stable
as $$
  select role from public.profiles where id = auth.uid()
$$;

create or replace function public.is_admin()
returns boolean
language sql
security definer
stable
as $$
  select public.current_user_role() = 'admin'
$$;

create or replace function public.is_editor_or_admin()
returns boolean
language sql
security definer
stable
as $$
  select public.current_user_role() in ('admin', 'editor')
$$;
```

Policies conceptuelles :

- `pages`: public select where `is_active = true`; admin/editor full update/insert; delete admin only.
- `seo`: public select; admin/editor write.
- `settings`: public select only where `is_public = true`; admin/editor read/write.
- `cms_sections`: public select; admin/editor write.
- `cms_services`: public select where `is_active = true`; admin/editor write; delete admin only.
- `cms_contact_settings`: public select where `is_public = true`; admin/editor write.
- `hero_slider`: public select where `status = true`; admin/editor write; delete admin only.
- `media_library`: public select where `is_public = true`; admin/editor write; delete admin only.
- `contact_messages`: no public select; insert through server action or restricted anonymous insert; admin/editor select/update; admin delete.
- `appointments`: no public select; insert through server action or restricted anonymous insert; admin/editor select/update; admin delete.
- `newsletter_subscribers`: no public select; anonymous insert if newsletter enabled; admin/editor select/update; admin delete.
- `activity_logs`: admin/editor select; service/admin insert; no normal update.
- `profiles`: self select limited, admin full; role changes admin only.

## 9. Storage cible

Bucket : `media`

Option recommandee au demarrage :

- Bucket public pour assets strictement publics du site.
- Bucket prive separe `private-media` si documents medicaux ou pieces sensibles apparaissent plus tard.

Regles :

- Interdire SVG ou sanitizer avant upload.
- Valider extension et MIME cote serveur.
- Limiter taille a 25 MB pour compatibilite avec PHP actuel.
- Conserver `media_library` comme index applicatif.
